# 系统数据库配置与切换系统设计规约

本文档详述了为 AI Token Monitor 设计的系统数据库配置系统的技术规约与交互体验设计。该系统允许用户在本地嵌入式 SQLite 与跨端网络数据库 PostgreSQL 之间自由切换、指定自定义路径、并支持免重启的一键测试和空库自动初始化表结构。

---

## 1. 目标与背景

AI Token Monitor 当前依靠单一的本地嵌入式 SQLite 作为全部历史会话与消耗 Token 数据的缓存层。为了进一步满足：
1. **多端看板数据共享**：在云端或跨设备的局域网内同步多用户、多客户端的 Token 消费数据。
2. **数据路径定制**：允许 SQLite 用户自定义 `.db` 物理文件的存储路径以避免 C 盘爆满或便于数据定期备份。
3. **极佳切换体验**：数据库切换保存时，不需要用户手动重启服务进程或关闭重启应用，通过“免重启·热重载连接池”机制即时无缝应用。

---

## 2. 界面与交互体验设计 (UI/UX)

本系统由**右上角配置按钮**以及**毛玻璃风格的配置弹窗组件**组成。

### 2.1 右上角配置按钮
* **物理位置**：Header 顶栏操作区中，位于“同步刷新”按钮的左边，以精美精致的齿轮 ⚙️ 图标（Lucide React Icon `Settings`）进行呈现。
* **视觉风格**：采用与整体系统高度一致的毛玻璃透明底板卡片与微交互动画。鼠标悬停时呈现霓虹青色（Neon Cyan）高亮旋转，点击后流畅平滑地呼出配置面板弹窗。

### 2.2 数据源配置弹窗
点击齿轮按钮后，会弹出全屏居中的玻璃态卡片配置弹窗：
1. **数据源切换 Tab**：
   * **选项 A (嵌入式 SQLite)**：默认状态。
   * **选项 B (PostgreSQL)**：网络数据库模式。
2. **SQLite 选项内容**：
   * **自定义数据库路径**：单行文本输入框，用户可以输入自定义绝对路径（如 `D:\my_cache\stats.db`）。
   * **默认提示小字**：显示当前的系统默认位置 `C:\Users\<username>\.ai_token_monitor\token_stats.db`。
3. **PostgreSQL 选项内容**：
   * **数据库连接串 (DATABASE_URL)**：统一的 URL 文本录入框。
   * **Placeholder / 示例**：显示默认占位符 `postgresql://your_username:your_password@host:5432/token_monitor`。
   * **说明文案**：提示用户可以直接粘贴 Supabase、Neon 等云数据库商提供的一键连接串。
4. **弹窗底部控制项**：
   * **⚡ 一键测试连接 按钮**：向后端触发测试请求。测试通过后弹出绿色成功提醒，若目标数据库为空库，则额外提示已顺利初始化表结构。
   * **💾 保存并应用配置 按钮**：将配置持久化写入 `.env` 并触发后端热重载，弹出成功通知后弹窗自动关闭，看板数据刷新。

## 3. 后端技术架构设计

后端依托于 Rust (Tauri v2 + Axum) 架构，我们设计了以下核心模块来承载配置保存、一键测试、多库桥接和热连接池重载：

### 3.1 统一多数据库桥接器 (DbAdapter Bridge)
为了在避免重复实现 `db.rs` 内部 1600 多行精细的 SQL 查询逻辑的前提下同时兼容 PostgreSQL，我们引入统一抽象层：

```rust
// 统一的参数类型映射
pub enum SqlParam {
    Text(String),
    Int(i64),
    Float(f64),
}

// 统一的数据库操作桥接 Trait
pub trait DbAdapter {
    fn execute(&self, sql: &str, params: &[SqlParam]) -> Result<usize, String>;
    fn query_row<T, F>(&self, sql: &str, params: &[SqlParam], mapper: F) -> Result<T, String>
    where
        F: FnOnce(&dyn RowWrapper) -> Result<T, String>;
    // ...以及其他列表查询方法
}
```

#### 🛠️ 动态 SQL 占位符归一化 (Placeholder Normalization)
* **核心挑战**：SQLite 占位符使用 `?`，而 PostgreSQL 使用顺序索引的 `$1, $2, $3`。
* **设计方案**：在 Postgres 驱动客户端执行 SQL 之前，底层 `DbAdapter` 的底层执行器会自动运用正则表达式检测 SQL 串，**在运行时将 `?` 动态转译为 `$1, $2, $3`**。
* **成果**：让庞大的 `db.rs` 中的 1600 行 SQL 查询逻辑一字不改，两端完美复用！

### 3.2 免重启 · 热连接池重载
* **连接管理器**：我们设计一个静态的全局连接管理者 `GLOBAL_DB_POOL` (例如基于 `Mutex<Option<DbPool>>` 或懒加载机制)。
* **配置动态加载**：
  每次数据库查询时，它会向该管理器请求活动连接。
  当用户执行 `/api/config/save` 保存新配置时，后端服务在向硬盘 `.env` 写入最新的 `DATABASE_TYPE`、`DB_SQLITE_PATH` 和 `DATABASE_URL` 之后，**会触发重置命令，清空已建立的缓存连接池**。
  在下一次数据请求呼入时，管理器检测到连接池为空，全自动根据最新的 `.env` 参数重新初始化连接池。实现真正意义上的热加载、零重启。

### 3.3 数据库表结构自动初始化 (Schema Auto-Migration)
无论是测试连接还是应用连接：
* 后端重载连接后，首要事务是执行 `DDL 校验`（即检查表 `sessions` 和 `turns` 是否已经建立）。
* 针对空数据库，后端连接池启动后将自动静默运行表迁移脚本（DDL），创建所有字段、外键级联关系、主键和联合索引，保证空库瞬间处于完美准备完毕的状态。

### 3.4 后端接口设计
* **`POST /api/config/test`**：
  * 参数：`{ db_type: "sqlite" | "postgres", sqlite_path?: string, pg_url?: string }`
  * 逻辑：建立临时的 3 秒超时限制驱动连接，若连通则对空库静默执行表结构自动建表，最终返回：
    `{ success: true, message: "连接成功且表结构校验完备！" }`
* **`POST /api/config/save`**：
  * 参数：`{ db_type: "sqlite" | "postgres", sqlite_path?: string, pg_url?: string }`
  * 逻辑：通过写 `.env` 文件修改配置项，随后主动清空热连接池，返回保存成功，由后续请求重新建立池。

## 4. 验证与测试方案

### 4.1 一键测试模块验证
* **测试用例 1 (SQLite 校验)**：
  在配置弹窗中输入自定义路径 `D:\ai_token_monitor_test\cache.db`，点击一键测试，检验是否能自动创建目录并生成 `.db` 文件、跑通建表。
* **测试用例 2 (Postgres 连通性校验)**：
  输入合法的本地或云端 PostgreSQL 空数据库 URL，点击测试，校验建表事务是否自动跑完，表格是否在数据库客户端内成功显示。
* **测试用例 3 (异常录入校验)**：
  输入不可达或格式错误的 PostgreSQL URL，校验界面是否能捕获具体的驱动报错并进行红色警示。

### 4.2 免重启数据切换验证
1. 打开应用，展示系统默认 SQLite 库的数据。
2. 点击右上角配置，切换到 PostgreSQL (配置一个准备了不同测试数据的 Postgres 库)，点击测试并保存。
3. 看板弹窗关闭后，刷新整个看板，检查是否有零秒中断、无需重启的过渡，直接无缝展现 Postgres 库下的统计明细。
